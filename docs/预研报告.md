## 摘要

本文给出 RM2027 基地颈部装甲板图传算法的稳定基线：HSV/几何 ROI
检测 → PAIR 成功时直接输出 → **PAIR 失败时红绿灯几何约束的
RG-SINGLE** → **恒速 Kalman** → 自适应 4:3 裁剪 → 320×240 → QPMAP →
低延迟 x264 → 300 B stream-packed → 解码 2× 显示。

**[实测]** 编码/链路基线保持冻结：目标 88 kbps、实际 75.72 kbps，
ROI-PSNR 中位 36.90 dB，红条成对检出率 51.5%，全帧平均 IoU 0.711，
非空检测率 91.5%，严格链路 demand 49 包/14,104 B、actual
50 包/15,000 B、覆盖率 100%、P95 帧龄 61.3 ms，四层硬门槛全过。
95 kbps 质量点实际 83.79 kbps，但 demand 52 包/15,101 B 超限，
只能作为质量上限；640×480 直接编码在 89.2 kbps 下 PAIR 仅 7.2%，
明确不可用。

**[实测]** 时序估计侧，第二轮 Kalman 在冻结测试集上 P95 |τ| 20.50 ms，
原 EMA 基线 74.50 ms（改善 72.5%）；中心 E95 8.38 px（EMA 19.61），
静态抖动 2.789 px（EMA 2.694，1.035×，硬门槛内），漏检 1–2 帧 E95
2.03 px（EMA 23.60），IoU 0.907（EMA 0.739）。慢速 30–100 px/s 的
P95 为 119.74 ms（EMA 113.55，+5.4%），机动组 43.01 ms（EMA 72.76）。

**[实测]** 旧 SINGLE 在 frame 102–155（约 3.4–5.2 s）会在两条红条
候选之间左右横跳，ROI 脱离装甲板。新 RG-SINGLE 在同一窗口把中位
偏差从 41.7 px 降到 7.7 px，>10 px 跳变从 28 次降到 0 次；代价是
框高标准差 3.76 px（LAMP-only 1.18，旧 SINGLE 11.67）。

**[实测]** 最终 RG 视频为 76.135 kbps、668 个 300 B 包、0 LOST。
ROS2 C++ 离线 demo 与 Python 参考实现的 H.264 码流 SHA256 完全一致，
17 项 GTest 全过。

**结论：建议冻结“PAIR + RG-SINGLE + 第二轮恒速 Kalman + 自适应
4:3 裁剪 + 320×240 QPMAP”为稳定基线。** 真实视频仍无人工逐帧 GT，
绝对精度与实车链路需后续补充验证。

## 1 概述

### 1.1 背景

RM2027 图传单包 300 B、总频率上限 50 Hz，理论总上限 15 kB/s
（120 kbps）。状态数据占用时隙：状态 10 Hz 时视频只剩 40 个时隙，
即 12 kB/s（约 96 kbps）。测试相机 1440×1080、25 mm 镜头，基地
颈部装甲板在 10–25 m 时只有约 102×52 到 41×21 像素；直接低码率
压缩整帧会先丢掉任务目标。

前期预研已验证：低延迟 x264 可把帧龄压到百毫秒级；300 B
stream-packed 比按帧补零省链路；块级 QPMAP 可在同码率下把比特
集中到 ROI；CQP 模式下编码器会忽略 ROI 量化偏移，必须使用 ABR。
本轮在此基础上补齐**检测退化时的几何稳定性**与**时序估计的
参数优化**，并把算法整理为可独立构建/测试的 ROS2 C++ 功能包。

### 1.2 预研目的

1. 在真实绕轨视频上稳定输出装甲板 ROI，覆盖 PAIR 正常与 PAIR 失效
   两种状态。
2. 用红条 + 绿灯的相对几何约束替换旧 SINGLE 的“任选一条红条”，
   消除左右横跳导致的 ROI 脱离。
3. 按 `agent.md` 的流程重新优化恒速 Kalman，冻结参数后在测试集
   只评估一次。
4. 把算法拆分为 `core / detection / estimation / coding / ros`
   五层，核心库不依赖 ROS，节点只做消息适配。
5. 用 C++ 复现 Python 最终码流，验证端口一致性。

### 1.3 研究边界

- 单段渲染绕轨视频，600 帧、20 s；不是多局真实比赛素材。
- 无人工逐帧真值；画质/检测指标使用检测器在原始帧上的平滑 ROI
  作为伪参考；时序指标来自合成解析真值。
- 只测 30 fps 源；25 fps、真实相机曝光、无线丢包、目标硬件算力
  未验证。
- 不评价弹道、落点或辅瞄算法；只评价图传画面与 ROI 时序估计。
- 链路为 300 B/50 Hz 的离线仿真，不是实车 0x0310 链路。

## 2 问题定义与目标

### 2.1 端到端指标

- **P95 帧龄**：源帧时间到解码输出时间，目标 ≤200 ms。
- **覆盖率**：成功解码帧数 / 应输出帧数，目标 ≥99%。
- **有效帧率**：30 fps 测试下目标 ≥29 fps。
- **平均有效负载**：视频有效字节 / 媒体时长，目标 ≤11.5 kB/s。
- **1 秒峰值**：任意 1 秒窗口内的视频包数/字节 + 10 Hz 状态包；
  总包数 ≤50、总字节 ≤15,000 B。
- **需求峰值与实际发送峰值分开**：队列可以摊平需求，但付出帧龄
  或丢帧代价。

### 2.2 算法指标

- **运动方向等效时间误差** `τ`：`1000·(p*-p̂)·v*/‖v*‖²`，`τ>0`
  表示沿运动方向落后；主口径只统计真值速度 ≥100 px/s（mid+fast）。
- **中心误差**：`‖p̂-p*‖₂`；LOST 帧按 1440×1080 对角线 1800 px
  计罚，同时单列有效帧误差。
- **静态抖动**：静止真值段去除平均偏差后的每轴标准差与二维 RMS。
- **IoU / 尺寸误差**：`IoU(B̂,B*)`、`|log(ŵ/w*)|`、`|log(ĥ/h*)|`。
- **漏检误差**：人为连续缺测 1/2/3/5 帧后预测与真值的 E95。
- **重获时间**：恢复有效检测后到误差回到 10 px 内并维持 2 帧的耗时。
- **单帧计算耗时**：只计估计器 `update`，不含检测/IO/绘图。

### 2.3 成功判据

1. 链路硬门槛：P95 ≤200 ms、覆盖率 ≥99%、有效 fps ≥29、
   平均 ≤11.5 kB/s、1 秒总包数 ≤50、总字节 ≤15,000 B。
2. QPMAP 质量门槛：同实际码率下 ROI-PSNR 比无 QPMAP 基线高
   ≥0.75 dB，或 PAIR 高 ≥5 个百分点，或 IoU 高 ≥0.03。
3. 分辨率门槛：320×240 在同实际码率下不劣于 400×300，并明显优于
   640×480 直编。
4. 时序门槛：抖动 ≤1.10× EMA、中心 E95 ≤1.05× EMA、漏检 E95
   ≤1.05× EMA、跟踪率 ≥EMA−0.005、无非有限/越界、update P95
   ≤1 ms。

## 4 算法原理与设计

### 4.1 总体 Pipeline

```text
1440x1080 BGR
  -> HSV 绿灯 + 红条 + PAIR
  -> PAIR 成功: 直接输出
     PAIR 失败: RG-SINGLE / RG-LAMP
  -> 恒速 Kalman（方法感知 R/门控）
  -> 自适应 4:3 裁剪 -> 320x240
  -> QPMAP BG+10/FG-5/NEUT0
  -> libx264 ABR 88k
  -> 300 B stream-packed 分包
  -> 重组 -> 解码 320x240 -> 2x 640x480
```

### 4.2 HSV/几何 ROI 检测

绿灯：HSV H 35–100、S≥40、V≥80；连通域面积/长宽比/fill 预筛；
椭圆拟合长短轴比 ≤3.5；取最大连通域，用 moments 求灯心，灯尺度
`ls=max(w,h)`。

红条：只在灯下方 ±3.5·ls、8·ls 的带内做红色分割（H≤12 或
H≥165，S≥55，V≥60）；连通域 → 轮廓 → `minAreaRect`；长/短 ≥1.4、
长边 0.12–1.0·ls、倾角 ≤75°。

配对：一左一右夹住灯心、间距 0.40–2.60·ls、高度相似 ≥0.20、
倾角差 ≤22°、对中点距灯心 ≤1.20·ls 且位于灯下方；按“离灯最近、
左右对称、间距接近 1.20·ls”打分选最优。PAIR ROI：
`cx=对中点x`、`cy=对中点y+0.05·sep`、`w=1.09·sep`、
`h=2.18·max(条高)`。

### 4.3 PAIR 失败：RG-SINGLE

旧 SINGLE 的缺陷：`bar=min(bars,key=cy)` 任选一条红条，按
`cx=bar.cx−side·0.65·ls` 反推中心；红条左右切换时中心跳变
约 `1.3·ls`。在 102–155 帧上观测到 537.7 / 585.5 两簇（相差
47.8 px），导致 ROI 脱离装甲板。

新方法（`detection/rg_detector.cpp`）：

1. **PAIR 帧标定模板**：`u_L=(R_L−G)/s`、`u_R=(R_R−G)/s`、
   `d=(C−G)/s`，以及 `w/s`、`h/s`、条高 `/s`；滚动窗口 60 帧，
   记录协方差。
2. **候选筛选**：按红条相对绿灯的侧别匹配左/右模板；马氏距离 +
   **归一化 y 残差门 0.8**。错误簇 y 残差约 1.3–1.5，正确簇约
   0.3–0.5；阈值 0.8 可拒绝错误簇而不依赖宽松的协方差。
3. **中心融合**：`C_G=G+s·d`、`C_R=R+s·(d−u_j)`、
   `C=λC_G+(1−λ)C_R`、`λ=rel_G/(rel_G+rel_R)`。没有可信红条时
   回落灯中心，不强行 SINGLE。
4. **输出**：`method ∈ {PAIR, RG_SINGLE, RG_LAMP}` 与
   `confidence ∈ [0,1]`，供 Kalman 调整观测噪声。

### 4.4 恒速 Kalman

状态 `x=[cx,cy,vx,vy,logw,logh,v_logw,v_logh]`，观测
`z=[cx,cy,logw,logh]`；F 为恒速模型，Q 为连续白噪声加速度模型，
R=diag(r_pos,r_pos,r_size,r_size)。实现要点：

- 有效观测才更新；`logw/logh` 保证尺寸正值；
- Joseph 形式协方差更新并强制对称；
- 创新 Mahalanobis 距离超过 `gate_chi2` 时拒绝本次观测，只预测；
- 连续拒绝后重初始化；非 PAIR 的重初始化门槛提高到 8 次；
- 缺测最多 `H=2` 帧，第 3 帧 `LOST`；重获后按新测量重初始化；
- 方法感知 R：PAIR 1×、RG_SINGLE 2×/conf、RG_LAMP 3×、
  旧 SINGLE/LAMP 12×。

**冻结参数**（第二轮 300 组验证集搜索；见 `rm2027_roi/config/kalman.yaml`）：

```yaml
q_pos: 1313.07
q_size: 0.000510016
r_pos: 25.3156
r_size: 0.016075
gate_chi2: 16.0
gate_reinit: 3
p0_vel: 283.212
p0_size_vel: 0.707658
hold: 2
```

### 4.5 自适应裁剪与 QPMAP

裁剪窗口：`Wc=clamp(4·max(roi_w,4/3·roi_h),192,400)`，`Hc=3/4·Wc`，
左上角按图像边界 clamp。画布 320×240；QPMAP 20×15 个 16 px 块，
背景 QP +10、前景 QP −5、无过渡环；AU-start 包携带 4 B 归一化
ROI（x,y,w,h 各 0–255）。

### 4.6 低延迟编码与分包

libx264 ABR 88 kbps、B=0、lookahead=0、AQ=2、mbtree=0、单线程、
preset faster、VBV 100 ms、GOP 60。300 B stream-packed：8 B 头
（seq、frame_id、valid_len、flags、ts_delta），首包携带 4 B ROI；
连续 H.264 字节跨 AU 打包，重组时按 seq 拼接。

### 4.7 ROS2 解耦

```
rm2027_roi/
├─ include/rm2027_roi/{core,detection,estimation,coding,ros}
├─ src/{core,detection,estimation,coding,ros,main.cpp}
├─ config/{detector,kalman,coding,pipeline}.yaml
├─ launch/roi_pipeline.launch.py
└─ test/{test_kalman,test_coding,test_geometry,test_pipeline}.cpp
```

- 核心库 `rm2027_roi_core` 不依赖 ROS，只依赖 OpenCV/Eigen；
- `roi_detector`：`image_raw → roi/detection`；
- `roi_estimator`：`roi/detection → roi/estimate`；
- `roi_crop`：`image_raw + roi/estimate → roi/canvas / roi/qmap /
  roi/normalized`；
- 功能包 `rm2027_roi` 内的 `msg/` 定义 `RoiDetection` / `RoiEstimate`；
- 离线 `offline_demo` 复用同一核心库，不依赖 ROS 运行时。

## 6 复杂度分析

- **[实测]** Kalman 单帧 `update` P95 0.0405 ms（Python 参考，
  仅计估计器）；C++ 实现结构相同，开销更低。
- **[实测]** C++ 离线 demo 600 帧端到端（OpenCV 解码 + 检测 +
  Kalman + 裁剪/QPMAP + 写 YUV）约 4.7 s（WSL2，单线程）；
  编码器 600 帧约 6.7 s。该数值不是目标硬件的实时性结论。
- 检测主要为 HSV 阈值、连通域、轮廓/椭圆拟合；在 1440×1080 上
  Python 参考约 15–20 ms/帧。C++ 端口未单独计检测耗时。
- QPMAP/分包为 O(块数)，可忽略；编码为主要耗时。

## 7 风险与挑战

1. **[待验证]** 真实视频无人工逐帧 GT；绝对定位精度与真实运动
   滞后未标定。3–5 s 的参考是“最后一次 PAIR 中心”，不是真值。
2. **[实测]** 慢速 30–100 px/s 的 P95 仍比 EMA 高 5.4%；若实际
   工况以慢速绕轨为主，需要重新评估是否保留 Kalman 或调整 R。
3. **[实测]** 机动组（加速/急停/反向/正弦/圆弧）P95 43.01 ms，
   已显著优于 EMA，但仍存在反向瞬间超调。
4. **[实测]** 旧 SINGLE 的左右横跳来自检测器回退策略，不是时序
   滤波器；RG-SINGLE 已修复，但依赖 PAIR 模板，PAIR 长时间丢失
   时只能回落灯中心。
5. **[待验证]** 单段渲染视频、PC/WSL 离线；真实相机曝光、白平衡、
   无线丢包、目标硬件算力、0x0310 链路未验证。
6. **[待验证]** 300 张合成图 GT 只覆盖单帧回退，不能标定 RG 的
   PAIR 序列模板；RG 的绝对精度仍需真实人工 GT。

## 8 结论与后续工作

### 8.1 结论

- 编码/链路冻结基线保持：88 kbps 目标、实际 75.72 kbps、四层
  硬门槛全过；95 kbps 只作为质量上限。
- 时序估计采用第二轮恒速 Kalman：P95 |τ| 20.50 ms，中心 E95
  8.38 px，漏检 E95 2.03 px，IoU 0.907；全部硬门槛 PASS。
- PAIR 失败采用 RG-SINGLE：102–155 帧中位偏差 41.7→7.7 px，
  >10 px 跳变 28→0；最终视频 76.135 kbps / 668 包 / 0 LOST。
- 算法已整理为 ROS2 Humble C++ 功能包，核心库与节点解耦，17 项
  GTest 全过，C++ 码流与 Python 参考逐字节一致。

### 8.2 后续工作

1. 对真实视频补 100–200 帧人工 ROI 标注，重算真实中心 E95、
   尺寸误差与运动滞后。
2. 在真实相机/无线链路/目标硬件上复测帧龄、覆盖率和检测稳定性。
3. 针对慢速段重新评估 Kalman 的 `r_pos` 或引入自适应 R；保持
   RG-SINGLE 的几何门控不变。
4. 将 `qpmap_encoder` 与 ROS2 节点接入实车 0x0310 发送链路。
